# Temporary deployment teardown checklist

This is a future **manual, separately authorized** procedure. Do not invoke it during local preflight. Terraform `destroy` is never automated by PAYFLOW. The named teardown owner records actual UTC times, resource inventories, and approvals in the deployment ticket.

1. Stop private demo traffic; record the last accepted request. Review pending dispatches, `PROCESSING` leases, unresolved provider outcomes, ledger issues, and active admin credential operations. Keep uncertain outcomes available for investigation and export only approved audit evidence.
2. Record the ECS service scale-down and last task stop times. Check API, worker, migration, and admin task histories and log retention. Scaling to zero **does not** stop RDS, NAT, ALB, Secrets Manager, ECR, or Temporal Cloud charges.
3. Review RDS backups and final-snapshot retention with the data owner. The Terraform RDS instance has `deletion_protection=true` and `skip_final_snapshot=false`; retain these safeguards through normal operation. A separately approved teardown must explicitly handle deletion protection, choose a unique final snapshot identifier if the configured name already exists, and record who owns snapshot deletion. A final snapshot and retained automated backups can incur storage charges after the instance is gone.
4. Reconcile Terraform state and the actual inventory, then execute any approved teardown through the infrastructure owner. Verify the two NAT gateways and associated Elastic IP allocations, internal ALB/listeners/target groups, ECS services/tasks/cluster, RDS, subnets and security groups, CloudWatch alarms/log groups, ECR images/repositories, and IAM attachments are removed or intentionally retained. Inspect deletion failures; do not assume command success means the account is empty.
5. Review Secrets Manager secret versions and per-merchant key secrets. The Terraform startup secret containers use a 30-day recovery window; scheduled deletion and retained versions can affect cleanup and charges. Record each secret's deletion state and owner. Retire the temporary merchant credentials through the approved private process. Do not expose secret values in the ticket.
6. Have the external owner retire the Temporal Cloud namespace/API key and verify its separate billing state. Private DNS, VPN/Direct Connect, ACM certificate, and remote Terraform state bucket may be shared resources; confirm ownership before changing them. Preserve state and audit records under the approved retention policy.
7. Record the actual last billable resource timestamp and compare it with the 24-hour or approved 48-hour window. Check AWS Cost Explorer/Bills or the account billing process after teardown and again when delayed metering appears. Investigate residual NAT, RDS snapshot, Secrets Manager, ECR, CloudWatch, data-transfer, state, and Temporal charges. Close the ticket only when the owner has reviewed the residual inventory and bill.

Use [temporary-deployment.md](temporary-deployment.md) for the cost assumptions and time-box worksheet. Do not remove TLS, backups, reconciliation, or private-network safeguards merely to simplify teardown.
